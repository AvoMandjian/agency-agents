# Mason Brick Integration Snippets by Agent Role

## For Project Initialization Agents (PM, Rapid Prototyper, Senior Developer)

### Complete Project Setup
```bash
# Full-stack Flutter application with Serverpod backend
mason make flutter_init --projectName ecommerce_app

# Generated structure includes:
# - BLoC cubits (auth, home, network, sign in/up, splash)
# - AutoRoute navigation with guards
# - Serverpod client integration
# - Firebase analytics and authentication
# - Multi-language support (en/ar)
# - Development and release environments
```

### Lightweight Project Setup
```bash
# Flutter app without backend dependencies
mason make flutter_init_no_backend --projectName portfolio_app

# Same architecture but:
# - Local auth simulation instead of Serverpod
# - No backend client dependencies
# - All other features intact (BLoC, routing, UI components)
```

### Post-Generation Steps
```bash
# 1. Generate routes
cd my_app
flutter pub run build_runner build --delete-conflicting-outputs

# 2. Generate localizations
flutter gen-l10n

# 3. Configure Firebase (if using flutter_init)
# - Add google-services.json (Android)
# - Add GoogleService-Info.plist (iOS)

# 4. Generate launcher icons
flutter pub run flutter_launcher_icons

# 5. Run first build
flutter run
```

## For Feature Development Agents (Frontend, Senior Developer, UI Designer)

### Screen Generation
```bash
# Generate complete screen with cubit and routing
mason make new_screen --screenName product_details

# Generated files:
# - lib/screens/product_details_screen.dart
# - lib/cubits/app_cubits/product_details_cubit/cubit.dart
# - lib/cubits/app_cubits/product_details_cubit/state.dart
# - routes/app_router.dart (updated with ProductDetailsRoute)
```

### State Management Generation
```bash
# Generate cubit with sealed state classes
mason make new_cubit --cubitName user_settings

# Generated files:
# - lib/cubits/app_cubits/user_settings_cubit/cubit.dart
# - lib/cubits/app_cubits/user_settings_cubit/state.dart

# Generated code includes:
# - Sealed class UserSettingsState
# - UserSettingsInitial, Loading, Success, Error states
# - UserSettingsCubit with initial state
```

### Integration Workflow
```bash
# 1. Generate screen
mason make new_screen --screenName checkout

# 2. Implement business logic in generated cubit
# Edit: lib/cubits/app_cubits/checkout_cubit/cubit.dart

# 3. Build UI in generated screen
# Edit: lib/screens/checkout_screen.dart

# 4. Add repository methods
# Edit: lib/repositories/checkout_repo.dart

# 5. Update routes (already done by Mason)
flutter pub run build_runner build

# 6. Test the feature
flutter test test/cubits/checkout_cubit_test.dart
```

## For DevOps Agents

### CI/CD Integration with Mason
```yaml
# .github/workflows/flutter-ci.yml
name: Flutter CI

on: [push, pull_request]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - uses: subosito/flutter-action@v2
        with:
          flutter-version: '3.24.0'
      
      - name: Install Mason
        run: dart pub global activate mason_cli
      
      - name: Get Mason bricks
        run: mason get
      
      - name: Install dependencies
        run: flutter pub get
      
      - name: Generate code
        run: flutter pub run build_runner build --delete-conflicting-outputs
      
      - name: Analyze code
        run: flutter analyze
      
      - name: Run tests
        run: flutter test --coverage
      
      - name: Build APK
        run: flutter build apk --release
```

## Common Mason Brick Workflows

### Workflow 1: New Feature Development
```bash
# 1. Generate screen with state management
mason make new_screen --screenName feature_name

# 2. Create repository for data layer
# Manually create: lib/repositories/feature_repo.dart

# 3. Implement business logic in cubit
# Edit: lib/cubits/app_cubits/feature_name_cubit/cubit.dart

# 4. Build UI in screen
# Edit: lib/screens/feature_name_screen.dart

# 5. Generate routes
flutter pub run build_runner build --delete-conflicting-outputs

# 6. Test
flutter test test/cubits/feature_name_cubit_test.dart
```

### Workflow 2: Add State Management to Existing Screen
```bash
# Generate just the cubit
mason make new_cubit --cubitName existing_feature

# Manually integrate into existing screen:
# - Add BlocProvider to wrappedRoute
# - Add BlocBuilder/BlocConsumer to build method
# - Wire up cubit methods to UI events
```

### Workflow 3: Multi-Feature Sprint
```bash
# Generate multiple features at once
mason make new_screen --screenName feature_one
mason make new_screen --screenName feature_two  
mason make new_screen --screenName feature_three

# Generate shared state management
mason make new_cubit --cubitName shared_data

# One build_runner pass for all
flutter pub run build_runner build --delete-conflicting-outputs
```

## Best Practices for Mason Brick Usage

### DO:
- Use Mason bricks for repetitive patterns (screens, cubits, full projects)
- Run `build_runner` after generating screens (for AutoRoute)
- Follow the generated structure and patterns consistently
- Customize generated code to add business-specific logic
- Test generated code as part of your test suite

### DON'T:
- Overwrite existing files without backing up
- Skip post-generation steps (build_runner, localization)
- Modify brick templates without understanding impact
- Generate code in wrong directories (follow brick structure)
- Ignore linting errors in generated code
